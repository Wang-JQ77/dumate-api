# 架构说明

本项目的技术原理与设计决策。面向想了解内部机制或二次开发的用户。

## 整体架构

```
┌──────────────────┐    HTTP     ┌──────────────┐    HTTP     ┌──────────────┐
│  你的 Agent       │ ──────────→ │  DuMate API  │ ──────────→ │  DuMate      │
│  OpenAI SDK /    │ ←────────── │  :8765       │ ←────────── │  opencode    │
│  Anthropic SDK / │             │              │             │  本地服务     │
│  Claude Code     │             └──────┬───────┘             └──────┬───────┘
└──────────────────┘                    │                            │
                                 ┌──────┴───────┐            ┌───────┴───────┐
                                 │  透传代理     │            │  百度云 API    │
                                 │  (按需启动)   │            │  (积分/模型)   │
                                 └──────────────┘            └───────────────┘
```

DuMate 桌面客户端运行时会在本机启动多个服务进程：

| 进程 | 作用 |
| --- | --- |
| `DuMate.exe` | Electron 主程序 |
| `dumate-main-server.exe` | 主服务 |
| `dumate-opencode.exe` | **任务执行引擎**（本项目的核心依赖），暴露会话/消息 HTTP 接口 |
| `dumate-router.exe` | 路由服务 |

本服务（`points_api.py`）不依赖其中任何一个的固定端口——全部动态发现。

## 三条链路

### 1. DuMate 进程发现（dumate_client.py）

所有对 DuMate 的调用都依赖从其进程环境中发现的三个变量：

| 变量 | 用途 |
| --- | --- |
| `DUMATE_HOST_URL` / `OPENCODE_SERVER_PORT` | opencode 服务地址（**端口随版本和启动变化**） |
| `DUMATE_INAPP_KEY` | opencode 请求鉴权头 `X-Dumate-Inapp-Key` |
| `DUMATE_USER_ID` | 默认工作目录的一部分 |

发现流程（Windows API，无需管理员权限）：

1. `tasklist` 按进程名找到 `dumate-main-server.exe` / `dumate-opencode.exe` 的 PID
2. `NtQueryInformationProcess` 拿到 PEB 地址
3. `ReadProcessMemory` 读取进程参数块中的环境变量区域（UTF-16 编码）
4. 解析出上述变量

也支持环境变量覆盖（`DUMATE_OPENCODE_URL`、`DUMATE_INAPP_KEY`），便于调试。

### 2. 积分查询（不消耗积分）

DuMate 不在本地存储积分数据，本服务直接调用百度云接口：

```
GET https://console.bce.baidu.com/api/dumate/points/quota_overview
```

鉴权使用 DuMate 保存在 `%APPDATA%\qianfan-desktop-app` 下的加密 cookie：

1. 读取 `auth.json` 中的密文和 `.cookie-key` 中的密钥
2. AES-256-GCM 解密得到登录 cookie（含 `sec-token` 等）
3. 携带 cookie 请求百度云接口
4. 结果缓存 60 秒（`/refresh` 端点绕过缓存）

cookie 过期时需在 DuMate 客户端重新登录，然后重启本服务。

### 3. 任务执行（消耗积分）

调用 opencode 的会话/消息接口：

```
POST /session                          → 创建任务（title + directory）
POST /session/{id}/message             → 发送消息并执行
GET  /session/{id}/message             → 读取消息与结果
```

三种模式通过请求头指定：`X-Dumate-AutoModel-Level: L0|L1|L2`（lite/turbo/ultra）。

`send_message` 是同步阻塞的——DuMate 完成整个任务（可能含多轮模型调用和工具执行）后才返回。因此同步模式最长等待 300 秒；异步模式在后台线程执行，立即返回后由客户端轮询。

## 透传代理机制（tools/start_proxy.py）

**为什么需要**：DuMate 的模型调用会读取其进程环境中的 `HTTP_PROXY`。这个地址继承自 DuMate **启动时**的 shell 环境——可能是用户代理软件的地址，也可能是早已失效的陈旧配置。当指向的端口没有服务监听时，DuMate 的所有模型调用直接失败。

**关键结论**：该端口**不是固定值**（可能是 8888、7890、7897 或没有），不能硬编码。

**自适应流程**（两处执行，结果互补）：

启动时（`start_points_api.bat` → `tools/start_proxy.py`）：

```
读取 DuMate 进程环境中的 HTTP_PROXY
    ├─ 未配置 → DuMate 直连，无需处理
    ├─ 端口有服务在监听 → 真实代理在运行，无需处理
    └─ 端口无服务（陈旧配置）→ 在该端口启动透传代理
```

运行时（`dumate_client.py` 的 `ensure_dumate_proxy`，创建客户端时惰性检查，30 秒节流）：

覆盖"本服务先于 DuMate 启动"的场景——启动时 DuMate 未运行、无法发现代理配置；等 DuMate 启动后，第一次任务执行会补做上述检查并按需启动透传代理。

透传代理（`transparent_proxy.py`）是纯 TCP/HTTP 转发：CONNECT 隧道直接对接远端，普通 HTTP 请求重写为绝对路径转发。DuMate 发出的模型请求经它转发到百度云，链路恢复。

由于只监听 `127.0.0.1` 且仅在本机使用，透传代理不会暴露到外网。

## OpenAI / Claude 兼容层（points_api.py）

本服务不是模型代理——**它没有自己的 LLM**。兼容层的工作是协议转换 + 路由：

### 请求路由（无工具声明时）

```
消息含积分关键词？──→ 直接返回余额 JSON（不消耗积分）
        │否
        ▼
消息 + 模式转发给 DuMate 对话（消耗积分，复用默认会话保持上下文）
```

### 工具调用协议（声明工具时）

两轮协议，服务端真实执行：

```
第一轮：客户端发消息
        └─→ 服务端按关键词路由到内置工具，返回 tool_call
             （get_points_balance / create_task / send_task_message / get_task_messages）

第二轮：客户端按标准协议回传工具结果占位
        └─→ 服务端识别"最后一条消息是工具结果"，真正执行工具
             （查余额 / 调 opencode 执行任务），返回最终结果
```

关键实现细节：**只有最后一条消息是工具结果时才执行**（历史中的工具结果不触发），这修复了"历史含工具结果导致后续所有请求被误判为第二轮"的 bug。

### 格式兼容

| 客户端格式 | content 类型 | 工具结果格式 |
| --- | --- | --- |
| OpenAI chat | `type: "text"` | `role: "tool"` |
| Responses | `type: "input_text"` | `function_call_output` 项 |
| Claude | `type: "text"` | user 消息中的 `tool_result` 块 |

Claude 格式中 `tool_result` 挂在 user 消息的 content 数组里，提取最近 assistant 的 `tool_use` 时不能遇 user 停止（与 OpenAI 格式不同）。

### 模型名解析

Claude Code 等客户端会发送自己的默认模型名（如 `claude-sonnet-4-5-xxx`）。`_resolve_level` 按档位关键词映射：haiku→lite、sonnet→turbo、opus→ultra，保证默认配置也能选到合理模式。

## 设计决策

- **单文件服务**：`points_api.py` 包含全部 HTTP 逻辑，部署和阅读成本低
- **只读积分 + 执行透传**：不提供记账/对账——积分数据以百度云为准，本服务只做查询与转发
- **动态发现优于配置**：端口、key、代理地址全部从运行环境发现，clone 即用，零配置
- **进程内缓存**：积分 60 秒缓存避免频繁请求百度云；默认会话复用保持对话上下文

```

├── dumate_client.py     # DuMate 封装：进程发现 + opencode 客户端
├── tools/
│   ├── transparent_proxy.py  # 透传代理（支持任意端口）
│   ├── start_proxy.py        # 代理智能启动器（自动发现端口）
│   ├── decrypt_cookies.py    # cookie 解密（积分查询用）

└── docs/                 # 文档
```
