# 常见问题

## 启动问题

### 双击 start_points_api.bat 没反应 / 闪退

确认 Python 已安装且在 PATH 中：

```bat
python --version
```

若提示找不到命令，重新安装 Python 时勾选 "Add Python to PATH"，或手动将 Python 目录加入系统环境变量。

### 端口被占用（8765）

API 服务固定使用 8765 端口。若被其他程序占用，修改 `start_points_api.bat` 中的两处端口号（检测和启动），并同步修改客户端的 base_url。

### 提示 "Service already running"

API 服务已在运行。如需重启，先运行 `stop_points_api.bat` 再启动。

## 任务执行问题

### 发送消息后一直等待 / 超时

按顺序排查：

1. **DuMate 客户端是否运行**：任务执行依赖 DuMate 的本地服务（opencode），客户端必须已启动并登录
2. **代理是否正常**：DuMate 的模型调用依赖其进程环境中的 `HTTP_PROXY` 地址。用 `start_points_api.bat` 启动会自动处理：读取 DuMate 期望的代理端口，无服务监听时在同端口启动透传代理。若手动改过环境变量导致 DuMate 代理配置异常，重启 DuMate 客户端后再重启本服务
3. **任务本身耗时**：复杂任务（生成大文件等）可能需要数分钟。可用 `sync: false` 异步模式 + 轮询，避免长连接超时

### 返回 502 (send message failed / read messages failed)

本服务连不上 DuMate 本地服务。常见原因：

- DuMate 客户端未运行或刚重启（端口会变化）——本服务每次请求前动态发现端口，但发现失败时回退到默认地址。重启本服务即可
- DuMate 重新登录后本地服务的鉴权 key 已更新——重启本服务

### 任务执行成功但没有生成文件

任务的工作目录由创建任务时的 `directory` 决定。未指定时使用 DuMate 默认目录。建议创建任务时显式指定：

```json
POST /api/tasks
{ "title": "写文件任务", "directory": "C:\\Users\\me\\workspace" }
```

## 积分问题

### 查询积分返回 401 / 失败（但任务执行正常）

积分查询走的是百度云接口（使用 DuMate 的登录 cookie），与任务执行链路（本地服务）不同。cookie 过期时：

1. 打开 DuMate 客户端确认登录状态，必要时重新登录
2. 重启本服务

### 积分消耗比预期多

- 每条转发给 DuMate 的消息（非积分查询）都消耗积分
- 未声明工具时，任何不含积分关键词的消息都会转发给 DuMate 对话并消耗积分——只想查余额就在消息里带上"积分"或"余额"关键词，或声明 `get_points_balance` 工具
- 复杂任务建议用 lite/turbo 模式，ultra 消耗更高

### 想确认积分消耗

调用前后各查一次余额对比：

```bat
curl -H "X-API-Key: <token>" http://127.0.0.1:8765/api/points/balance
```

## 认证问题

### 401 Unauthorized

- 检查请求头：`X-API-Key` 或 `Authorization: Bearer`（大小写不敏感）
- Token 以 `token.txt` 内容为准。若怀疑 Token 失效，删除 `token.txt` 后重启服务会生成新 Token（旧 Token 立即作废，所有客户端需更新）

### Token 泄露了怎么办

删除 `token.txt`，重启服务。新 Token 自动生成，旧 Token 失效。本服务只监听 `127.0.0.1`，外网无法访问；泄露通常发生在 Token 被提交到公开仓库——**永远不要把 `token.txt` 提交到 git**（.gitignore 已排除）。

## Agent 接入问题

### OpenAI SDK 报 "model not found"

`base_url` 必须以 `/v1` 结尾：

```python
client = OpenAI(base_url="http://127.0.0.1:8765/v1", api_key="<token>")
```

模型名用 `dumate-lite` / `dumate-turbo` / `dumate-ultra` / `dumate-points`。

### Claude Code 连接失败

确认三个环境变量（在启动 claude 的同一终端中设置）：

```bat
set ANTHROPIC_BASE_URL=http://127.0.0.1:8765
set ANTHROPIC_AUTH_TOKEN=<token>
set ANTHROPIC_MODEL=dumate-ultra
```

`ANTHROPIC_BASE_URL` 不要带 `/v1` 后缀（Anthropic SDK 会自动拼接）。

### Agent 发什么消息都返回同一段固定文案

那段文案是本服务的兜底回复。出现原因通常是消息未匹配任何路由（积分关键词、任务关键词、工具声明）。若 Agent 使用 Responses API 且消息 content 用了 `[{"type": "input_text", ...}]` 格式，本服务已兼容；仍有问题可检查 Agent 是否真的把用户消息放进了 `messages`/`input` 字段。

### 工具调用第二轮没有返回真实数据

确认回传格式：

- OpenAI 格式：最后一条消息 `role: "tool"`，且其上方有带 `tool_calls` 的 assistant 消息
- Responses 格式：最后一个 input 项是 `function_call_output`
- Claude 格式：最后一条 user 消息含 `tool_result` 块

服务端只在"最后一条消息是工具结果"时才执行工具，历史中的工具结果不会触发重复执行。

## 服务管理

### DuMate 重新登录后需要做什么

重启本服务（`stop_points_api.bat` → `start_points_api.bat`）。登录态变化会更新本地服务的鉴权 key 和积分查询的 cookie。

### 如何查看服务是否在运行

```bat
curl http://127.0.0.1:8765/health
```

返回 `{"status": "ok"}` 即在运行。

### 开机自启动

将 `start_points_api.bat` 的快捷方式放入启动目录（`Win+R` 输入 `shell:startup`）。注意 DuMate 客户端需先登录，建议在 bat 开头加延时等待。
